# Ham Watch — Flutter mobile app (consumer)

Native Android/iOS client for the ham/ugstream API. Built against the live
API (`docs/mobile-app-integration.md`). This folder contains the app source
(`lib/`, `test/`, `pubspec.yaml`); the platform folders (`android/`, `ios/`)
are generated by Flutter — see setup below.

## Features
- Phone + OTP login, secure token storage, **automatic token refresh**
  (no 15-min "session timeout").
- Home: billboard + Continue Watching + New/Movies/Series/Top 10 + genre rails.
- Search, Title detail (+ My List), Series episode lists.
- **Native HLS/MP4 player** (ExoPlayer/AVPlayer) with resume + progress saving.
- Paywall handling (402 → subscribe).
- Subscribe: plans + **card (hosted redirect)** and **mobile money
  (prompt + poll)** — with an editable payer number.
- Profile: edit name (required) / email / address; logout.
- Bottom-nav shell (Home · Search · My List · Profile).

## Setup (first time)
Requires the Flutter SDK (https://docs.flutter.dev/get-started/install).

```bash
cd mobile

# 1. Generate the android/ + ios/ platform folders around this source.
#    (flutter create overwrites pubspec.yaml + lib/main.dart with defaults —
#     restore ours right after.)
flutter create --org com.sentepos --project-name ham_watch --platforms android,ios .
git checkout pubspec.yaml lib/main.dart      # restore our versions

# 2. Deps + run
flutter pub get
flutter run                                   # on a connected device/emulator
```

Point at a different backend if needed:
`flutter run --dart-define=API_BASE=https://ham.sentepos.com/api/v1`

## Android network + player config
After `flutter create`, ensure `android/app/src/main/AndroidManifest.xml` has:
```xml
<uses-permission android:name="android.permission.INTERNET"/>
```
(Flutter adds this by default.) HLS/MP4 over HTTPS needs no extra config.

## Test
```bash
flutter test          # runs test/ (model-parsing + logic)
flutter analyze       # static analysis / lints
```

## Build the Android APK (for the login-page download link)
```bash
flutter build apk --release \
  --dart-define=API_BASE=https://ham.sentepos.com/api/v1
# output: build/app/outputs/flutter-apk/app-release.apk
```
Then host it so the web login-page button can serve it, e.g. copy to the
backend's static uploads:
```bash
cp build/app/outputs/flutter-apk/app-release.apk \
   /root/ugstream/backend/uploads/ham-watch.apk
# → served at https://ham.sentepos.com/api/uploads/ham-watch.apk
```
The web login page shows a **"Download Android app"** button pointing at
`NEXT_PUBLIC_ANDROID_APK_URL` (set it to that URL in the frontend `.env`).

## Not included (deferred — need backend/ops work)
- Offline **downloads** (needs a download API + DRM).
- **Push notifications** (FCM/APNs setup).
- **Chromecast/AirPlay**.
- Payment **deep-link** return (currently the app polls status, which works
  for both card and mobile money; a deep link is a nicer UX for card).
